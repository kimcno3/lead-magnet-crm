# v0.1.0 관리자 UI 구현 계획 (이슈 #11)

- Spec: [docs/PLAN.md](../PLAN.md), [CLAUDE.md](../../CLAUDE.md). 백엔드 API는 `backend/`의 컨트롤러와 springdoc(`/v3/api-docs`)이 기준이다.
- 브랜치 `feat/11-admin-web`. ADR 0011 관리자 UI.

## Global Constraints

- 보안 불변식(CLAUDE.md 그대로):
  - access token은 메모리(모듈 변수 또는 React 상태)에만 둔다. `localStorage`, `sessionStorage`, IndexedDB, 쿠키에 쓰지 않는다.
  - refresh는 HttpOnly 쿠키라 JS가 읽지 않는다. 앱 시작 시 `POST /api/admin/auth/refresh`로 세션을 복원하고, API가 401이면 refresh를 한 번만 시도한 뒤 원 요청을 다시 보낸다(동시 401은 refresh 하나를 공유). refresh가 실패하면 로그인 화면으로.
  - 로그인·refresh·logout 요청에는 `Authorization` 헤더를 붙이지 않는다(만료된 토큰이 있으면 Resource Server가 401을 낸다).
  - 업로드 HTML 미리보기는 `<iframe sandbox="allow-scripts allow-forms" srcdoc>`로만 렌더링한다. `allow-same-origin` 금지. `dangerouslySetInnerHTML` 금지.
  - 관리자 화면 응답에 CSP를 붙인다(nginx와 Vite dev 모두): `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; font-src 'self' data:; connect-src 'self'; frame-src 'self'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'`. srcdoc 미리보기는 이 정책을 상속하므로 관리자 출처에서는 업로드 HTML의 스크립트가 실행되지 않는다(정적 미리보기). 동작까지 보려면 공개 URL을 연다. 근거는 ADR 0011.
- 스택: React 19 + Vite + TypeScript(strict). 라우팅은 `react-router`(최신 7.x, data router 없이 `BrowserRouter`로 충분). 그 밖의 의존성은 최소로. UI 컴포넌트 라이브러리, CSS 프레임워크, 차트 라이브러리를 쓰지 않는다. 스타일은 CSS 파일(CSS 변수로 토큰 정의).
- 폰트: 외부 CDN 금지(CSP). 시스템 폰트 스택 `"Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Noto Sans KR", system-ui, sans-serif`. 숫자는 `font-variant-numeric: tabular-nums`.
- 모든 문구는 한국어. 날짜·숫자는 `Intl`(ko-KR, Asia/Seoul).
- 에러는 백엔드 ProblemDetail(`detail`, `code`, `errors[{field, message}]`)을 그대로 보여준다. 폼 필드 오류는 해당 입력 옆에.
- 스크립트: `npm run lint`(oxlint --deny-warnings), `npm run typecheck`, `npm test`(vitest), `npm run build`가 모두 통과해야 한다.

## 디자인 방향 (AI 템플릿처럼 보이지 않게)

- 성격: 매일 쓰는 내부 운영 도구. 마케팅 랜딩이 아니다. 밀도 있는 표와 숫자가 주인공. 장식보다 정보 위계.
- 금지: 그라데이션 배경, 글래스모피즘, 이모지 아이콘, 의미 없는 일러스트, 과한 그림자, 모든 것을 카드로 감싸기, 보라-파랑 AI 팔레트, 둥근 모서리 남발(반경은 4~6px), 히어로 섹션, "Welcome back!" 류 문구.
- 팔레트: 따뜻한 회색 중립(배경 `#FAFAF8` 계열, 텍스트 `#1C1B19` 계열, 경계선 `#E7E5E0` 계열) + 강조색 하나(진한 녹색 `#1F6F4A` 계열: 전환·주요 버튼). 상태 색은 절제(published 녹색, draft 회색, closed 적갈색 텍스트 배지). 채널 구분은 색보다 이름과 위치로, 막대는 강조색 하나의 명도 차이로.
- 레이아웃: 왼쪽 고정 사이드바(제품명 "리드마그넷 CRM", 메뉴: 캠페인, 템플릿; 하단에 운영자 이메일과 로그아웃), 본문 최대 폭 1200px. 페이지 제목은 왼쪽 정렬, 주요 행동 버튼은 제목 줄 오른쪽.
- 타이포: 본문 14px/1.5, 표 13px, 페이지 제목 20px 600. KPI 숫자 28px tabular-nums.
- 접근성: 모든 입력에 label, 포커스 링 보이게, 색만으로 상태를 구분하지 않음, 버튼은 `<button>`, 표는 `<table>`, 실시간 메시지는 `aria-live`.
- 빈 상태·로딩·오류 상태를 모든 목록에 둔다(빈 상태는 다음 행동을 알려주는 한 문장 + 버튼).

## 화면

1. **로그인** `/login`: 이메일, 비밀번호, 로그인 버튼. 401이면 "이메일 또는 비밀번호가 올바르지 않습니다". 성공 시 원래 가려던 경로로.
2. **캠페인 목록** `/campaigns`: `GET /api/admin/stats/campaigns`(지표 포함)와 캠페인 목록을 합쳐 표로 보여준다: 이름, 상태, 기간, 방문, 방문자, 신청, 전환율. 행 클릭 → 상세. "새 캠페인" 버튼 → 생성 다이얼로그(이름, 설명, 시작·종료일).
3. **캠페인 상세** `/campaigns/:id`: 제목 줄(이름, 상태 배지, 보관 버튼), 탭 세 개.
   - **성과**: 기간 필터(시작일·종료일 date input, 비우면 전체), KPI 5개(방문, 방문자, 신청, 전환 방문자, 전환율 %), 채널별 표(채널, 방문, 방문자, 신청, 전환율, 신청 수 막대). 지표 정의를 KPI 아래 작은 글씨 한 줄로("전환율 = 신청한 방문자 / 방문자").
   - **폼**: 폼 목록(제목, slug, 상태, 게시일). "새 폼" → 템플릿 선택, 제목, 동의 문구, slug(선택). 폼 행을 펼치면: 상태 행동(게시, 마감, 확인 다이얼로그), 공개 URL(`{PUBLIC_BASE_URL}/f/{slug}`), 배포 링크 4채널(없으면 "링크 만들기", 있으면 URL과 복사 버튼, UTM 표시), 필드 설정 표(draft일 때 label·required 수정).
   - **명단**: 폼·채널 필터, 표(신청일, 이름, 전화번호, 이메일, 채널, 폼, 추가 항목 요약), 페이지 이동(20개씩). 전화번호는 `010-1234-5678` 형식으로 표시.
4. **템플릿 목록** `/templates`: 표(이름, 크기, 필드 수, 등록일). "HTML 업로드" → 파일 선택(.html, 드래그 앤 드롭 지원) + 이름. 422면 코드별 안내 문구(예: `template_contact_field_missing` → "phone 또는 email 이름의 입력이 있어야 합니다").
5. **템플릿 상세** `/templates/:id`: 왼쪽 추출된 필드 표(이름, 유형, 필수, 라벨, 선택지), 오른쪽 미리보기 iframe(sandbox="allow-scripts allow-forms", srcdoc=content, 높이 640px, 테두리). 미리보기 위에 "관리자 화면에서는 스크립트 없이 정적으로 표시됩니다" 안내.

`PUBLIC_BASE_URL`은 링크 응답의 `url`에서 얻거나(링크가 있으면), Vite 환경 변수 `VITE_PUBLIC_BASE_URL`(기본 `http://localhost:8081`)로 둔다. docker build 인자로도 넘길 수 있게 Dockerfile에 `ARG`.

## 테스트 (vitest + Testing Library, fetch는 `vi.fn`으로 대체)

- api client: 로그인 후 토큰이 Authorization 헤더에 붙는다, 401 → refresh 1회 → 재시도, 동시 401 두 개가 refresh를 한 번만 부른다, refresh 실패 → 로그아웃 상태, 로그인·refresh 요청에는 Authorization이 없다, `localStorage`·`sessionStorage`의 `setItem`이 한 번도 호출되지 않는다(spy).
- 로그인 화면: 성공 시 이동, 401 문구.
- 템플릿 상세: iframe의 `sandbox` 속성이 정확히 `allow-scripts allow-forms`이고 `allow-same-origin`이 없다, srcdoc에 content가 들어간다, 필드 표.
- 캠페인 성과: KPI 숫자 포맷(전환율 0.6667 → "66.7%"), 채널 5개 행.
- 명단: 페이지 이동이 page 파라미터를 바꾼다, 전화번호 포맷.
- 템플릿 업로드 422: 코드별 안내 문구.
- format.ts 단위 테스트.
