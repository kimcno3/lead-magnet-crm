## Task 51: 로그인 시도 제한과 프록시 뒤 실제 IP (이슈 #51)

브랜치 `feat/51-login-throttle-proxy-ip`.

- **실제 IP**: docker compose에서 관리자 요청은 admin-web nginx를 거친다. nginx가 `X-Forwarded-For`/`X-Real-IP`를 붙이므로(확인하고 없으면 nginx.conf에 추가), backend는 `server.tomcat.remoteip.*`로 신뢰 프록시를 설정해 `getRemoteAddr()`가 실제 클라이언트 IP를 돌려주게 한다. 신뢰 프록시 대역은 설정값(`TRUSTED_PROXIES`, 기본: 사설 대역 정규식이 아니라 compose 네트워크 대역 또는 Tomcat 기본 internal-proxies)으로 두고, 공개 포트(:8081)는 앞단 프록시가 없으므로 XFF를 신뢰하면 안 된다. 포트별로 다르게 다뤄야 하면 커스텀 필터로 admin 커넥터에서만 XFF를 읽는다. 위조 XFF를 공개 포트에서 보내도 무시되는 테스트, admin 포트에서 신뢰 프록시를 거친 XFF는 반영되는 테스트.
- **로그인 제한**: 이메일(정규화)별·IP별 실패 횟수 슬라이딩 윈도. 기본 이메일 5회/15분, IP 20회/15분 초과 시 429 `too_many_login_attempts`(Retry-After). 성공하면 해당 이메일 카운터 초기화. 계정 존재 여부를 드러내지 않게 없는 이메일도 같은 규칙. 인메모리(LRU 상한), 다중 인스턴스 한계는 ADR에 기록. 거절은 감사 로그에 행마다 쓰지 않고 집계(ADR 0016 지침), 잠금 시작 시점은 `auth.login.locked` 한 행.
- ADR 0021 로그인 시도 제한과 신뢰 프록시. ADR 0016·0019 변경 기록(IP 출처).
- 관리자 화면: 로그인 429 문구("잠시 후 다시 시도해 주세요(약 N분)").

## Task 52: payload의 연락처 모양 추가 항목 (이슈 #52)

브랜치 `feat/52-extra-contact-fields`.

- TemplateInspector에 `extra_contact_field`(warning): `phone`/`email` 외에 `type=tel`/`type=email` 이거나 이름이 전화·이메일을 뜻하는(phone, tel, mobile, hp, email, mail 포함) 필드. 문서(AI_FORM_PROMPT, TROUBLESHOOTING) 갱신.
- 명단 응답·마스킹 CSV에서 payload 중 해당 필드(fieldConfig의 type이 tel/email) 값을 같은 마스킹 규칙으로 가린다. 원문 CSV와 원문 열람 API에는 원문. 원문 열람 응답에 `extraContacts`(필드명→원문) 추가 여부는 판단해 ADR 0015 변경 기록.
- 파기(익명화)는 이미 payload 값을 비우므로 그대로.
