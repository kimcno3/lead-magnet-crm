# 0009. 운영자 시드

- 상태: 승인
- 날짜: 2026-10-23

## 맥락

과제 범위에는 회원가입이나 운영자 관리 화면이 없다. 그래도 인증한 운영자만 관리자 기능에 접근해야 하므로 첫 운영자 계정을 만들 방법이 필요하다. 계정 정보를 코드나 마이그레이션에 넣으면 시크릿이 저장소에 남는다.

## 결정

- 기동 시 `ADMIN_SEED_EMAIL`, `ADMIN_SEED_PASSWORD` 환경 변수로 운영자 한 명을 만든다(`OperatorSeeder`).
- 둘 다 비어 있으면 건너뛴다. 하나만 있거나 형식이 잘못되면 기동을 실패시킨다. 설정 실수를 조용히 넘기지 않기 위해서다.
- 같은 이메일의 운영자가 이미 있으면 아무것도 바꾸지 않는다. 환경 변수로 비밀번호가 바뀌는 경로를 만들지 않는다.
- 이메일은 소문자로 정규화해 저장하고 DB에서도 `ck_operators_email_lower`와 유니크 인덱스로 막는다.
- 비밀번호는 12자 이상, UTF-8 72바이트 이하(BCrypt 입력 한계)만 받는다. `{bcrypt}` 접두사가 붙은 DelegatingPasswordEncoder 형식으로 저장한다.
- 로그에는 마스킹한 이메일만 남긴다.

## 고려한 대안

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
|---|---|---|---|
| Flyway 데이터 마이그레이션 | 단순 | 해시라도 계정 정보가 저장소에 남고 환경별로 바꿀 수 없다 | 시크릿 커밋 금지 |
| 회원가입 API | 표준적 | 공개된 가입 경로가 생긴다 | 범위 밖이고 공격면이 늘어난다 |
| CLI 명령 | 기동과 분리 | Docker Compose 한 번으로 재현하기 어렵다 | 실행 절차가 늘어난다 |

## 결과

- `docker compose up` 한 번으로 로그인 가능한 상태가 된다.
- 비밀번호 변경과 운영자 추가는 지원하지 않는다. 필요해지면 관리자 API로 추가한다(로드맵).
