# 0013. 캠페인·폼 상태 모델

- 상태: 승인
- 날짜: 2026-10-23

## 맥락

운영자는 캠페인을 만들고, 업로드한 HTML 템플릿으로 공개 신청 폼을 만든다. 폼은 이후 배포 링크, 방문, 신청의 기준이 되므로 언제 수정할 수 있고 언제 신청을 받는지가 명확해야 한다. 템플릿은 나중에 다시 올릴 수 있지만 이미 게시한 폼의 필드가 바뀌면 쌓인 신청 데이터와 어긋난다.

## 결정

- 캠페인 상태는 `active → archived` 한 방향이다. 보관한 캠페인에는 새 폼을 만들 수 없다(409 `campaign_archived`). 이미 있는 폼은 그대로 둔다. 다시 보관하면 409 `campaign_already_archived`다. 보관한 캠페인의 이름·기간 수정은 막지 않는다.
- 폼 상태는 `draft → published → closed` 한 방향이다. 그 밖의 전이는 409 `invalid_form_transition`이다(draft를 바로 닫거나 closed를 다시 게시하는 경우 포함). 게시·마감 시각은 `publishedAt`, `closedAt`에 남긴다.
- 폼 내용(`title`, `consentText`, `fieldConfig`의 `label`·`required`)은 draft에서만 수정한다. 그 밖의 상태에서는 409 `form_not_editable`이다. 한 요청에 내용 수정과 `status` 전이가 같이 오면 수정을 먼저 적용하고 전이한다.
- `fieldConfig`는 폼을 만들 때 템플릿 `fields`를 복사한 스냅샷이다. 이후 템플릿이 바뀌거나 지워져도 폼은 영향받지 않는다. 제출 검증(이슈 #8)은 이 값을 기준으로 한다. 수정할 때는 기존 필드와 이름 집합이 같아야 하고(추가·삭제·이름 변경은 422), 필드별로 `label`·`required`만 반영한다. `type`·`options`는 요청 값을 무시하고 기존 값을 유지한다.
- 동의 문구 `consentText`는 필수다(1~2000자). 개인정보 수집 동의를 폼마다 명시하기 위해서다.
- `slug`는 `^[a-z0-9][a-z0-9-]{1,62}[a-z0-9]$`(3~64자)이다. 생략하면 `SecureRandom`으로 소문자+숫자 8자를 만들고 충돌하면 5번까지 다시 뽑는다. 계속 충돌하면 409 `slug_taken`이다. 직접 준 slug가 중복이어도 409이고, 동시 요청으로 `ux_forms_slug` 유니크 위반이 나면 같은 코드로 바꾼다.
- PATCH는 없는 필드를 "바꾸지 않음"으로 해석한다. 날짜를 비우는 동작은 지원하지 않는다. 캠페인 PATCH의 `status`는 `"archived"`만, 폼 PATCH의 `status`는 `"published"`, `"closed"`만 받고 그 밖의 값은 422다.
- 상태 값은 DB CHECK 제약에 맞춰 소문자로 저장하고(`AttributeConverter`), API도 같은 값을 쓴다.
- 캠페인 목록의 `formCount`는 폼 상태와 무관하게 센다. `updated_at`은 모든 변경에서 주입한 `Clock`으로 갱신한다.

## 고려한 대안

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
|---|---|---|---|
| 게시 후에도 문구·필드 수정 허용 | 오타를 바로 고칠 수 있다 | 이미 받은 신청과 현재 폼이 어긋난다 | 데이터 일관성이 우선이다. 고치려면 새 폼을 만든다 |
| `fieldConfig`를 템플릿에서 매번 읽기 | 복사 불필요 | 템플릿 변경이 게시된 폼에 번진다 | 스냅샷이 제출 검증의 안정적 기준이다 |
| 마감한 폼 재게시(closed → published) | 운영 유연성 | 게시 기간 집계가 모호해진다 | 지표 정의를 단순하게 유지하려고 막는다 |
| slug를 항상 서버 생성 | 충돌 처리 단순 | 운영자가 읽기 쉬운 주소를 못 쓴다 | 선택 입력으로 둘 다 지원한다 |

## 결과

- 신청을 받는 폼은 게시 이후 필드가 고정되어 검증과 통계가 흔들리지 않는다.
- 잘못 게시한 폼은 고칠 수 없고 마감 후 새 폼을 만들어야 한다.
- 폼 삭제, 캠페인 복원(unarchive), 폼 복제는 지원하지 않는다. 필요해지면 새 ADR로 다룬다.

## 변경

### 2026-10-23: 캠페인 기간은 v0.1.0에서 안내용이다

- 캠페인 `startsAt`·`endsAt`은 v0.1.0에서 표시용 정보일 뿐이다. 기간이 지나도 폼은 자동으로 마감되지 않고(마감은 운영자가 폼을 `closed`로 바꾼다), 지표의 기간도 캠페인 기간이 아니라 요청의 `from`·`to`로만 정한다(ADR 0005). 기간에 맞춘 자동 마감이나 기본 지표 기간이 필요해지면 새 ADR로 다룬다.
