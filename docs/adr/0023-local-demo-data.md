# 0023. 로컬 데모 데이터

- 상태: 승인
- 날짜: 2026-10-24

## 맥락

처음 써 보는 사람은 `scripts/local-up.sh`로 띄운 뒤 빈 화면에서 시작했다. 템플릿을 올리고 캠페인·폼·링크를 만들고 방문과 신청을 몇 건 흉내 내야 성과 탭, 크리에이터 순위, 명단 페이지, 마감·초안 상태를 볼 수 있었다. E2E가 남긴 데이터("마케팅 자동화" 등)는 맥락 없이 흩어져 있어 제품이 어떻게 쓰이는지 보여 주지 못한다.

전제는 다음과 같다.

- 예시는 실제 회사(GLOW UP RIZZ)의 사업 라인(아카데미, MCN, 커머스 요고, F&B)을 본뜨되 **사람은 모두 지어낸다**. 실제 소속 크리에이터 이름·핸들은 쓰지 않는다. 신청자 이름도 가상이고 전화번호는 실제로 쓰지 않는 `010-5555-xxxx` 블록, 이메일은 `example.com`만 쓴다.
- 신청 연락처는 가상이어도 실제 제출과 **같은 개인정보 경로**를 지나야 한다. 그래야 원문 보기·CSV·키 교체·파기가 예시 데이터에서도 그대로 동작하고, "예시라서 평문"이라는 예외가 생기지 않는다.
- 운영 DB에 들어가면 안 된다.

## 결정

`demo` 패키지의 `DemoDataSeeder`가 기동 직후(`ApplicationReadyEvent`, 운영자 시드와 개인정보 키 확인 뒤) 예시 데이터를 넣는다.

- **기본은 꺼짐**: `app.demo.enabled`(환경 변수 `DEMO_DATA`, 기본 `false`). `.env.example`도 `false`이므로 CI·E2E 워크플로에서는 넣지 않는다. `scripts/local-up.sh`가 `.env`를 **새로 만들 때만** `DEMO_DATA=true`로 바꾼다(이미 있는 `.env`는 건드리지 않는다).
- **빈 DB에만 한 번**: 운영자가 있고 캠페인이 하나도 없을 때만 넣는다. 다음 기동은 캠페인이 있으므로 아무것도 넣지 않는다(멱등). 운영자가 없으면(`ADMIN_SEED_EMAIL` 비움) 건너뛴다. 생성자(`created_by`)는 가장 먼저 만든 운영자다.
- **도메인 서비스 사용**: 템플릿 업로드(검사 포함), 캠페인·폼 생성, 게시·마감, 크리에이터 등록·보관, 링크 생성은 운영자 API가 쓰는 서비스 그대로다. 게시 스냅샷, 템플릿 → 폼 잠금 순서, 폼 × 채널 × 크리에이터 링크 하나 규칙이 지켜진다.
- **방문·신청은 리포지토리로**: 지난 21일(Asia/Seoul)에 흩어 놓아야 해서 공개 API를 거치지 않고 `Visit.record`·`LeadRepository.insertIfAbsent`로 넣는다. 신청 입력은 실제 제출과 같은 `SubmissionValidator`로 검증·정규화하고, 연락처는 `ContactProtector`(`PiiCipher`·`PiiHasher`)로 암호화·해시하며, 동의 증빙은 `ConsentEvidence.of(폼 문구)`다. 원문은 DB에도 로그에도 남지 않는다. 각 신청의 `visitor_id`는 그 폼을 방문한 방문자다(전환 방문자 지표가 의미 있다). 봇 UA 방문은 `BotUserAgents`로 판정해 `is_bot`으로 남긴다.
- **시각 맞추기**: 서비스는 현재 시각으로 만들므로, 끝에 JDBC로 템플릿·크리에이터·캠페인·폼(생성·게시·마감)·링크 시각을 방문 기간 앞으로 옮긴다. 캠페인 목록은 `created_at` 내림차순이라 카탈로그 순서(아카데미 → MCN → 요고 → F&B)대로 보이도록 뒤 캠페인일수록 한 시간씩 앞당긴다. 감사 로그 시각은 옮기지 않는다.
- **감사 기록**: 폼 게시·마감과 크리에이터 보관은 서비스가 감사 기록을 남긴다(캠페인 보관은 원래 감사 대상이 아니다). 주체는 운영자를 사칭하지 않도록 `operator_id`·IP가 없고 User-Agent가 `lead-magnet-crm demo seeder (DEMO_DATA)`인 `AuditActor`다. "명단 조회"·"원문 보기" 같은 열람 기록은 만들지 않는다(검토자의 실제 조회가 진짜 기록으로 쌓인다).
- **결정적**: 난수 시드가 고정이라 같은 설정이면 같은 사람·값이 나온다. 로그는 건수만 한 줄(`예시 데이터 생성: …`)이다. 실패하면 예외 종류만 WARN으로 남기고 앱은 계속 뜬다.
- 의존 방향: `demo`는 도메인 패키지를 참조하지만 어떤 패키지도 `demo`를 참조하지 않는다(`PackageDependencyRulesTest`).

넣는 것: 템플릿 4(`resources/demo/*.html`, 검사 결과 없음), 캠페인 4(요고만 보존 기간 180일, 행사가 끝난 F&B는 폼을 마감한 뒤 `CampaignService`로 보관), 폼 5(게시 3, 마감 1, 초안 1), 크리에이터 5(보관 1), 링크 26, 방문 약 950(봇 약 20), 신청 95.

## 고려한 대안

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
|---|---|---|---|
| SQL 덤프·Flyway 반복 마이그레이션으로 넣기 | 빠르고 단순 | 연락처를 암호화하려면 키가 필요한데 키는 DB 밖에 있다. 평문 덤프는 개인정보 경로를 우회한다. 마이그레이션은 운영에도 적용된다 | 같은 개인정보 경로와 "운영에서 꺼짐"을 지킬 수 없다 |
| E2E·스크립트로 공개 API를 호출해 넣기 | 실제 제출 경로를 100% 지난다 | 시각을 과거로 둘 수 없어 기간 필터·추이가 의미 없고, 작성 시간 토큰·rate limit을 우회하는 장치가 필요하다 | 21일에 흩어진 데이터를 만들 수 없다 |
| 항상 켜고 프로필(`local`)로만 구분 | 설정이 하나 줄어든다 | compose 기본 프로필이 `local`이라 운영 실수로 켜지기 쉽다 | 명시적 플래그가 더 안전하다 |
| 실제 크리에이터 이름 사용 | 회사 맥락이 더 실감 난다 | 실존 인물의 이름을 가짜 성과·명단에 붙이게 된다 | 가상 인물만 쓴다 |

## 결과

- 검토자는 `scripts/local-up.sh` 한 번으로 성과 탭(채널·크리에이터 순위), 명단 여러 페이지, 마감·초안 폼, 보관된 크리에이터, 봇 제외, 보존 기간 차이를 바로 본다.
- 빈 DB로 시작하려면 `.env`에서 `DEMO_DATA=false`로 바꾸고 `scripts/local-up.sh --fresh`.
- 시드가 중간에 실패하면 이미 만든 캠페인 때문에 다음 기동에서도 건너뛴다. 이때는 `--fresh`로 다시 시작한다(로컬 전용이라 트랜잭션 하나로 묶는 복잡도를 들이지 않았다. 링크 생성은 코드 충돌 재시도 때문에 자기 트랜잭션에서 돈다).
- 여러 인스턴스가 동시에 빈 DB로 뜨면 둘 다 넣을 수 있다. 로컬 단일 인스턴스만 대상이라 잠금을 두지 않았다. **운영에서는 켜지 않는다.**
- 템플릿을 고치면 `DemoTemplatesTest`가 폼 계약과 "검사 결과 없음"을 확인한다.
